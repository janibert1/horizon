# hplug: server-side plugins for Horizon (Rust), Paper-shaped

- `sdk/` the facade crate (`hplug`): Plugin builder over Horizon's `mod_api::Hooks`/`Host`. ~300 lines.
- `plugins/<name>/` one crate per plugin exporting `pub fn plugin() -> hplug::Plugin`, plus `test.script`.
- `runner/` GENERATED by `hp gen`: the engine executable linking every plugin (same as the launcher's trait-mod `main`).
- `testclient/` `hp-client`: scripted headless protocol client (offline mode) with `expect` assertions.
- `hp` the CLI: `new`, `build`, `test`, `run`, `list`. See `hp` docstring.
- `PAPER_MAPPING.md`, `PORTING_GUIDE.md`, `../tools/scan_plugin.py` (compat scanner).
Needs a Horizon checkout with prepared 26.3 game data (`horizon-prepare`, see ../NOTES.md) and Rust. Linux or macOS. Plugins are compiled into the engine: no hot reload; plugins run unsandboxed.
Workspace: root `Cargo.toml` gets members `hplug/sdk`, `hplug/runner`, `hplug/testclient`, `hplug/plugins/*` (the only change outside `hplug/`).

## Requirements (Linux and macOS identical, verified on Fedora 43 x86_64 and macOS 12 Intel)
- Rust (stable, edition 2024 capable), python3, `nice` (coreutils). No Java at runtime; Java 25 only for `horizon-prepare`.
- Prepared game data in `.local/horizon-client/26.3` (or `HP_RESOURCES`), from your own Mojang files via `horizon-prepare`.
- 8+ GB free RAM for the first build (4 GB VPS: the build is OOM-killed). Linux binaries link only libc/libm/libgcc_s and need glibc <= 2.39, so they run on Debian 13 (netcup) too.
- `HP_JOBS` (cargo jobs, default 4), `HP_PROFILE` (fast|release), `HP_PORT` (default 25570; tests use +1).
